# EXAF Staff Workplace Platform — API (NestJS + Prisma)

Auth, RBAC, attendance (9:00–17:00 WAT), projects/tasks, generalized staff requests, Redis cache, Zod validation, local/S3 uploads.

There is **no public self-signup**. An admin (`users:create`) creates accounts via `POST /auth/register` or `POST /users`; staff complete their profile after first login.

## 1. Start Postgres + Redis

```bash
docker compose up -d
```

## 2. Install and configure

```bash
pnpm install
cp .env.example .env
```

Edit `.env`:
- `JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET` (e.g. `openssl rand -hex 32`)
- `SEED_SUPERADMIN_EMAIL` / `SEED_SUPERADMIN_PASSWORD`
- `COMPANY_EMAIL_DOMAIN` (defaults to `extensionafrica.com`)
- `DATABASE_URL` and `DIRECT_URL` (same value unless you add a pooler)

Then generate the Prisma client and run the first migration:

```bash
pnpm prisma generate
pnpm prisma migrate dev --name init
pnpm prisma db seed
```

## 3. Run the API

```bash
pnpm start:dev
```

API: `http://localhost:5002`. Health: `GET /health`. Swagger Docs: `http://localhost:5002/api/docs`.

Local avatars are served from `/uploads/...`. Set `STORAGE_DRIVER=s3` plus the `AWS_*` vars in production.

## First login flow

1. `POST /auth/login` with the seeded superadmin → `accessToken`, `refreshToken`, `mustChangePassword`.
2. `POST /auth/register` or `POST /users` (Bearer token, `users:create`) to create staff. Required: `email`, `firstName`, `lastName`, `roleNames`. Temporary passwords are **auto-generated by the backend**, sent via Nodemailer, and printed to the terminal console (`console.log`) during development.
3. Staff log in with the temporary password, then `PATCH /users/me` and/or `POST /users/me/avatar` to finish their profile. `POST /auth/change-password` clears `mustChangePassword`.

Emails must be `@COMPANY_EMAIL_DOMAIN` (e.g. `a.user@extensionafrica.com`).

## Design notes

- **Zod** — one `*.schemas.ts` per module; `ZodValidationPipe` on each body. Types come from `z.infer<>`.
- **Redis cache-aside** — role→permissions on login; staff directory and project list GETs. Mutations delete the matching key immediately. If Redis is down, an in-memory fallback is used.
- **Roles in the database** — seed includes `FINANCE_LEAD` and `OPERATION_LEAD`. Superadmin can `POST /roles` and `PATCH /roles/:id/permissions` (`roles:manage`) to add e.g. `MARKETING_LEAD` without a code change. New permission *keys* still need a seed/code entry because they gate routes.
- **Attendance** — WAT is UTC+1 with no DST. Check-in after 09:00 WAT → `LATE`. Check-out before 17:00 WAT → `leftEarly: true`.
- **Screentime & App Monitoring** — `POST /screentime/log` accepts telemetry (active/idle seconds, device info, top apps breakdown) from desktop agents or staff clients. `GET /screentime/me` retrieves personal logs, while `GET /screentime` (gated by `screentime:view_all`) provides admin/management reports.
- **Activity Trail & Audit Logs** — Every action across auth, attendance, projects, tasks, requests, and user provisioning generates an `ActivityLog`. Superadmin/HR can query global audit logs (`GET /activities` gated by `activities:view_all`). Staff can view their timeline (`GET /activities/me`).
- **In-App Notifications** — `GET /notifications` (paginated list with `link` deep-links), `GET /notifications/unread-count` (UI header bell badge), `PATCH /notifications/:id/read` & `PATCH /notifications/read-all`.
- **Projects & Tasks** — `GET /projects` and `GET /projects/:id` are accessible to all authenticated staff members.
- **Requests** — `StaffRequest.category` is a string allow-list: `LEAVE`, `TRAVEL`, `EQUIPMENT`, `REPAIR`, `REIMBURSEMENT`, `OTHER`. Dates required only for leave/travel. `notifyToEmails` / `notifyCcEmails` trigger SMTP if configured; Angular can autocomplete against `GET /users`.
- **Uploads** — `STORAGE_DRIVER=local` writes under `uploads/`; `s3` uses the AWS SDK.
- **Swagger Documentation** — Interactive API Explorer served at `http://localhost:5002/api/docs`.

## Adding a new permission-gated route

1. Add the key to `PERMISSIONS` in `prisma/seeds/seed.ts`.
2. Attach it in the `ROLES` map (or later via `PATCH /roles/:id/permissions`).
3. Re-run `pnpm prisma db seed` (idempotent).
4. Guard the route with `@RequirePermissions('your:key')`.

## Prisma schema layout

Multi-file schema under `prisma/schema/` (`schema.prisma`, `user.prisma`, `rbac.prisma`, `auth.prisma`, `attendance.prisma`, `project.prisma`, `request.prisma`, `screentime.prisma`, `activity.prisma`, `notification.prisma`).
